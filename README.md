# Enterprise Healthcare Data Platform (EHDP)

A healthcare data engineering project that builds a unified platform from synthetic hospital and clinical records. The repository contains source datasets, ingestion scripts, data-quality reports, warehouse SQL, Pentaho jobs, a Gold analytical layer, metadata documentation, and tests.

> **Data privacy:** The project uses synthetic healthcare data generated by [Synthea](https://synthetichealth.github.io/synthea/). It is intended for learning, data engineering, and analytics; it does not use real patient records.

## Project objectives

- Integrate healthcare data from CSV and JSON sources.
- Preserve raw source data in the Bronze layer.
- Profile, standardize, and validate data for downstream use.
- Model healthcare information for reporting and analysis.
- Build analytical dimensions, facts, and data marts.
- Document metadata, data lineage, and validation evidence.
- Maintain automated repository checks and tests.

## Architecture

```text
Synthea CSV / JSON datasets
          |
          v
Bronze layer — raw ingestion
          |
          v
Silver layer — profiling, cleansing and data-quality checks
          |
          v
Warehouse / Gold layer — dimensions, facts and analytical marts
          |
          v
Healthcare reporting and analytics
```

PostgreSQL is used for database-oriented ingestion and warehouse SQL. Python supports ingestion, profiling, and tests; Pentaho Data Integration jobs and transformations are included for ETL workflows. The repository also includes a Power BI star-schema artifact.

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/Harish2404lll/DataEngg_Industrial_Learning.git
cd DataEngg_Industrial_Learning
```

### 2. Create a virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure PostgreSQL

Create or select a PostgreSQL database and configure the connection string in the environment. For PowerShell:

```powershell
$env:UC2_DATABASE_URL = "postgresql+psycopg2://USER:PASSWORD@localhost:5432/uc2"
```

Replace the example credentials and database name with your local configuration. Do not commit passwords or other secrets to GitHub.

The ingestion scripts accept a source directory and write to the configured PostgreSQL schema. For example, with your source files arranged in a CSV folder:

```powershell
python bronze/ingestion/ingest_csv_sources.py --source-dir datasets --schema bronze
```

For JSON sources, use a directory containing the relevant JSON files:

```powershell
python bronze/ingestion/ingest_json_sources.py --source-dir datasets --schema bronze
```

The sample commands assume the selected folder contains the source files for that format. Run each script's `--help` option to see available options. Execute the SQL scripts in the intended order and configure the source paths and database schemas for your environment before running the full pipeline.

## Run tests

```bash
python -m pytest tests/ -v
```

Some database-backed tests are skipped unless `UC2_TEST_DATABASE_URL` is configured. Set it to the test database connection string before running those checks. The test suite includes basic checks, Silver transformation-rule tests, and optional database checks for expected raw tables and Gold views.

## Continuous integration

GitHub Actions workflow definitions are stored in `.github/workflows/`. The CI workflow is configured to run Python checks, verify expected directories, and execute pytest for pushes to `main` or `develop` and pull requests targeting `main`.

## Notes

- The source datasets are synthetic and may be large; ensure adequate disk space before cloning or processing them.
- Run database operations against a development or test database first.
- The SQL and ETL workflow may require environment-specific connection details and execution order.
- Report files document profiling and validation outputs; rerun the pipeline when source data or transformation rules change.
